# Finova Multilingual Support & Financial Assistant

## MVP delivered
- i18n configuration for English, Hindi (Devanagari) and Hinglish.
- Language picker and persistent browser preference.
- Locale foundation separated from business logic so new languages are translation/configuration work.
- Deterministic multilingual assistant for expense, income, outstanding, customer balance and recorded profit queries.
- Hindi Devanagari + Roman Hindi normalisation for common financial phrases.
- INR formatting with Indian grouping.
- Assistant answers are calculated from the signed-in Finova workspace; figures are never generated by an LLM.
- Existing browser voice input remains available through the assistant UI; language-aware speech recognition uses the selected locale in the updated assistant component.

## Safety architecture
Natural-language understanding should produce structured intent/entities only. A deterministic query executor must read the authenticated user's workspace. No raw SQL is accepted from an LLM and imported customer/invoice text is treated as untrusted data.

## Language workflow
1. Add language metadata in `src/lib/i18n/translations.ts`.
2. Add ICU-compatible translation resources as the catalog grows.
3. Native-speaker review of finance terminology.
4. Missing keys fall back to English and can be logged for translation review.
5. Add language-specific evaluation fixtures before release.

## Phase roadmap
- MVP: English/Hindi/Hinglish interface foundation + five deterministic assistant intents.
- V1: full app string extraction, ICU runtime, Marathi/Gujarati/Tamil/Telugu/Bengali/Kannada/Malayalam/Punjabi, multilingual invoice/reminder documents, voice language selection and query evaluation sets.
- Advanced: Urdu RTL, regional-language NLU, TTS provider adapters, WhatsApp assistant, proactive insights and human translation workflow.

## Assumptions / limitations
- The existing Finova data model is the source of truth.
- This build does not fabricate cloud LLM, translation-management, SMS, WhatsApp or TTS credentials.
- Browser speech recognition varies by browser and language. Production voice requires a tested Indian-language STT/TTS provider.
- Full extraction of every existing hard-coded string is a separate migration; the i18n foundation is added without pretending every legacy module is already translated.
- Financial/legal figures should be verified before filing or legal use.

## UX and voice update
- Full-app language selection remains in Settings → Language. The Finova AI panel has its own AI-language selector with Auto-detect and persists `finova-ai-language`.
- The assistant passes its selected language to both assistant API routes and selects `en-IN` / `hi-IN` speech recognition plus a matching browser TTS voice.
- Missing translation keys fall back to English in development and are logged for review.
- Voice wake-word privacy and browser limitations are documented in `docs/VOICE_ASSISTANT.md`.

## Runtime environment variables
- `FINOVA_AI_RATE_LIMIT_MAX=8`
- `FINOVA_AI_RATE_LIMIT_WINDOW_MS=60000`
- `REDIS_URL` optionally enables the shared sliding-window limiter; `REDIS_TOKEN` supports Redis REST deployments.
- `NEXT_PUBLIC_SUPPORT_EMAIL` configures the public support address.
- `NEXT_PUBLIC_QUIKIT_AUTH_ENABLED` controls the client QuikIT identity seam.
